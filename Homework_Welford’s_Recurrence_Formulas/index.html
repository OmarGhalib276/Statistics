Welford's recurrences, and what a hacker's scores can tell us.

Computing a mean and a variance usually means storing every value and going over them twice. Welford's recurrences do it in a single pass, one value at a time. This page shows where they come from and how they reduce to three lines of code.

Then it puts them to work. Many hackers attack many systems, every attempt earns a score from 0 to 10, and the page checks how the sampling mean and variance of each hacker relate to the true mean μ and variance σ² behind the scores. You can change every parameter and run it again.

Deriving Welford's formulas

Take the observations x1, x2, … as they arrive. After k of them there are two running quantities to keep: the mean and the sum of squared deviations (SS).

Mk = (1/k) Σi=1..k xi    SSk = Σi=1..k (xi − Mk)²

The point is to update M and SS using only their previous values and the new observation, so that earlier data never needs to be stored or re-read.

Step 0 · Knuth's recurrence for the mean

Multiplying the definition of the mean by k gives the running total, which grows by exactly one observation per step:

k·Mk = (k−1)·Mk−1 + xk

Subtract k·Mk−1 from both sides and divide by k:

Mk = Mk−1 + (xk − Mk−1) / k

The new mean is the old mean moved by a fraction 1/k of the "surprise" δk = xk − Mk−1. Initial value: M0 = 0.

Steps for the sum of squares

  1. Rewrite SS without the mean inside the sum. Expanding the square and using Σxi = k·Mk:
    SSk = Σ xi² − 2Mk Σ xi + kMk² = Σi≤k xi² − kMk²
  2. Take the difference between two consecutive steps. All terms with i < k cancel in the sum of squares, leaving only the new square:
    SSk − SSk−1 = xk² − kMk² + (k−1)Mk−1²
  3. Eliminate (k−1)Mk−1. From Step 0, (k−1)Mk−1 = kMk − xk, so (k−1)Mk−1² = Mk−1(kMk − xk). Substituting:
    SSk − SSk−1 = xk(xk − Mk−1) − kMk(Mk − Mk−1)
  4. Use Knuth's update inside the second term. Since Mk − Mk−1 = (xk − Mk−1)/k, the factor k cancels:
    SSk − SSk−1 = (xk − Mk−1)·(xk − Mk)

Welford's recurrence for the sum of squares (initial value SS0 = 0):

SSk = SSk−1 + (xk − Mk−1)(xk − Mk)
Sanity check. With δk = xk − Mk−1 we have xk − Mk = δk(k−1)/k, so the increment equals δk²(k−1)/k ≥ 0. The sum of squares can therefore never decrease, which the naive formula Σx² − (Σx)²/k does not guarantee in floating point.

The variance

The sampling (unbiased) variance divides by k−1, defined for k ≥ 2:

sk² = SSk / (k − 1)

A recurrence directly on the variance follows by multiplying by k−1 and using the result above, (k−1)sk² = SSk and (k−2)sk−1² = SSk−1:

sk² = ((k−2)/(k−1))·sk−1² + δk² / k   (k ≥ 2)

For k = 2 the first term vanishes (factor k−2 = 0), so s2² = δ2²/2, which is exactly the variance of two points. The variance with divisor k (the one that treats the data as the whole population) is SSk/k.

The code

The core is three lines. Start from mean = 0 and ss = 0, increase the counter k, and run them for each new value x.

// JavaScript: the three lines of the core
const delta = x - mean;        // delta_k = x_k - M_(k-1)
mean += delta / k;             // Knuth:   M_k  = M_(k-1) + delta_k / k
ss   += delta * (x - mean);    // Welford: SS_k = SS_(k-1) + delta_k * (x_k - M_k)

As a complete function (used by the experiments on this page):

function welford(xs) {
  let k = 0, mean = 0, ss = 0;
  for (const x of xs) {
    k++;
    const delta = x - mean;
    mean += delta / k;
    ss   += delta * (x - mean);
  }
  return { mean, variance: k > 1 ? ss / (k - 1) : NaN };
}

Why not the textbook formula?

The familiar shortcut s² = (Σx² − (Σx)²/n)/(n−1) is algebraically identical but subtracts two huge, nearly equal numbers. The test below uses the ten values 1…10 shifted by a constant C; the variance does not depend on C and is exactly 82.5/9 ≈ 9.1667 for every row.

Shift CNaive formulaWelfordTrue value

Values in red are wrong by more than 1%. Welford works on deviations from the running mean, which stay small whatever the offset, so it does not suffer from this cancellation.

Sampling mean and variance across many hackers

Every penetration attempt gets a score in {0, 1, …, 10}. The scores come from a fixed distribution of our choice. The default is Binomial(10, p) with p = 0.4: a system is protected by 10 independent controls, each one bypassed with probability p, and the score is the number of controls the hacker bypassed. Its theoretical values are

μ = 10p   σ² = 10p(1 − p)   ⇒   μ = 4   σ² = 2.4   (for p = 0.4)

There are m hackers, and each of them attempts n systems, which gives a trajectory of n scores. Welford's formulas are applied to each trajectory, so every hacker ends with one sampling mean x̄ and one sampling variance s². Averaging these m numbers gives the two averages that are compared with μ and σ².

Conclusions

  • The two averages land on μ and σ². The mean of the m sampling means is very close to μ, and the mean of the m sampling variances is very close to σ², for every n tried, even n = 5. In theory this is unbiasedness: E[x̄] = μ and, thanks to the divisor n − 1 (Bessel's correction), E[s²] = σ². The leftover differences are Monte Carlo noise of the order of the spread of one estimate divided by √m. The last column of the sweep table shows the contrast: with divisor n, the average settles on ((n − 1)/n)σ², visibly too low for small n.
  • Why this matters in inferential statistics. In practice we observe a single sample (one hacker's n scores, one audit) and we do not know μ and σ². Unbiasedness says that this one estimate is not systematically too high or too low: if the same audit were repeated many times, the estimates would be centred on the truth. That is what justifies using x̄ and s² in estimation, in confidence intervals such as x̄ ± t · s/√n, and in hypothesis tests, where s² is plugged in for the unknown σ².
  • More systems per hacker, less variability. The centre does not move with n, but the spread does. For independent scores, Var(x̄) = σ²/n, so the standard deviation of the sampling means falls like 1/√n: quadrupling n halves it. The sampling variance behaves the same way, with Var(s²) = (1/n)(μ4 − ((n − 3)/(n − 1))σ⁴), where μ4 is the fourth central moment of the scores; it is finite because scores are bounded, so Var(s²) also decreases as 1/n. Both estimators therefore converge to their targets as n grows (consistency, the law of large numbers), and the straight lines of slope −1/2 in the log–log charts show it.
  • The role of m. Increasing m does not make an individual hacker's estimate better; it only makes the two averages and the histograms more stable, because it reduces the Monte Carlo error of the experiment itself.
  • Why Welford. Each trajectory is processed in one pass with constant memory, no score has to be stored, and the update uses deviations from the running mean, which keeps it accurate where the textbook formula collapses.
