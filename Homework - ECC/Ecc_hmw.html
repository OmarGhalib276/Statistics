Elliptic-Curve Scalar Multiplication

Introduction

This web application explores the foundational mechanics of Public-Key Cryptography using Elliptic Curve Cryptography (ECC), similar to the secp256k1 curve used in Ethereum and Bitcoin.

Instead of unimaginably large numbers, we are using a "toy" finite field modulo 17 ($p = 17$). The curve is defined by the equation $y^2 \equiv x^3 + 7 \pmod{17}$.

The Core Concept: A private key ($k$) is simply a scalar integer. The public key ($Q$) is a point on the curve generated by adding a publicly known Base Point ($G$) to itself $k$ times ($Q = kG$). While computing $Q$ from $k$ is computationally easy (using point addition and doubling), determining $k$ from $Q$ relies on the Elliptic Curve Discrete Logarithm Problem (ECDLP), which is practically unsolvable for large fields.

Cryptographic Properties

  • Distribution & Uniformity: The generated points are not uniformly distributed across all integer coordinates. They are strictly confined to values satisfying the curve equation (where $x^3+7$ is a quadratic residue modulo 17). However, within this restricted set, the sequence of jumps $G, 2G, 3G...$ scatters points pseudo-randomly across the valid geometric space.
  • Bit Distribution: Even in this toy model, analyzing the binary representation of the generated coordinates shows a relatively balanced mix of 0s and 1s, preventing attackers from guessing coordinate regions based on simple bit-biases.
  • Avalanche-like Behavior & Correlations: Changing the private key $k$ by just $1$ causes the resulting point coordinates to jump wildly across the modulo grid. Statistical analysis (Pearson correlation) shows near-zero linear correlation between the input $k$ and the output coordinates $(X, Y)$. This lack of predictable geometric proximity or smooth gradient is the essence of the ECDLP's difficulty.
  • One-Way Function vs. Hash Function:
    • Cryptographic Hash Functions (e.g., SHA-256): Designed to completely destroy algebraic structure. They require a strict avalanche effect (a 1-bit input change flips ~50% of output bits) to prevent pre-image attacks.
    • ECC One-Way Functions: Rely on the discrete logarithm problem. Unlike hashes, ECC must preserve an underlying algebraic group structure (e.g., $kG + jG = (k+j)G$). This homomorphic property allows for digital signatures (ECDSA) and key exchanges (Diffie-Hellman). ECC is not a hash function; it is a structured one-way function where reversing the path without the discrete steps is infeasible due to the chaotic modulo wrapping, not the destruction of algebra.
